# SA 布局参数实验

在仓库根目录运行，Python 仅使用标准库：

```bash
# Linux：先检查编译器。需要 C++20 和 std::format，建议 GCC 13 或更新版本。
g++ --version

# 冒烟：case1 的重复默认配置和五个参数变体，共7次布局。
python3 algorithm/SA-Placement/run_experiments.py --smoke --cxx g++ --jobs 4

# 正式实验：5参数 × 5取值 × 4测例，共100次，自动构建两种宽度后连续串行执行。
python3 algorithm/SA-Placement/run_experiments.py --cxx g++ --jobs 4
```

上传时保留完整仓库的相对目录结构，包含当前 `source/`、四个 `test/config/case*` 及本目录。
不需要 xmake、Qt、Catch2、SAT 求解器或 Gurobi；使用原有解析器、NetBuilder、布局器和硬件模型，
为满足其链接关系编译非 SAT 的核心源码，但不调用布线流程。
`--jobs` 只控制并行编译，不并行运行实验；服务器内存不足时调小。
macOS 可以使用默认 `c++`，或者 `--cxx clang++`。

可从任意工作目录启动脚本。所有新增文件、源码副本、编译产物和日志均在本目录内。
脚本不改根目录构建配置，也不修改 `source/` 或 `test/`。
构建缓存以源码、实验代码和编译器指纹区分，上传时可不带 `.build/`、`logs/`。
编译器自身可能使用操作系统临时目录。

## 实验设置

| 参数 | 基准 | 五档取值 |
| --- | ---: | --- |
| init_temp | 100 | 10, 30, 100, 300, 1000 |
| freeze_temp | 0.5 | 0.01, 0.1, 0.5, 1, 5 |
| solve_num | 50 | 10, 25, 50, 100, 200 |
| cooling_rate | 0.97 | 0.80, 0.90, 0.95, 0.97, 0.99 |
| max_no_improvement | 50 | 5, 10, 25, 50, 100 |

每次重读原始输入，模式为0，不合并多模式。固定随机种子默认 `20261023`。
每个参数分组均独立执行默认配置，不复用其他组的结果，因此正式运行确为100次。
每层尝试 `solve_num × N` 次；停滞上限为 `max_no_improvement × max(1, floor(N/2))`。
case1/5 的 COB 宽度为12，case7/12 为13。脚本在本目录内复制源码并分别编译，避免混用宽度。

## 记录文件

每次启动生成独立的 `logs/sweep-时间-标识/` 或 `logs/smoke-时间-标识/`：

- `runner.log`：总进度、每次目标值、耗时和错误。
- `manifest.json`：完整参数计划、种子、平台、编译器、源码指纹、输入文件哈希和完成状态。
- `build-width12.log` / `build-width13.log`：构建命令、诊断和缓存使用情况。
- `results.csv`：每次运行的全部参数、实际预算、目标值、改善比例、耗时、停止原因、操作计数及合法性。
- `tables.md`：每个参数一张表，行是case，列是参数值，并说明固定参数。
- 每次运行子目录中的 `debug.log`、`console.log`、`iterations.tsv`、初始/最终位置表、`result.json` 和 `command.json`。

温度层日志包含该层实际使用的温度、当前/已保存最优目标、停滞层数及累计候选/接受/拒绝次数。
无效候选次数为总尝试次数减去接受与拒绝次数，包含无空闲位置等提前跳过的操作。
布局耗时包含布局日志开销，不包含解析、线网构建、编译和布线；单次计时不适合微小性能差异比较。
最终目标值重新计算并校验与恢复的层末最优值一致，执行 Release 下仍生效的占用和位置检查。

完整四测例扫参结束时自动更新本目录 `experiments.md`；冒烟及选择部分case的运行不覆盖该文件。
单次布局失败/超时会记录失败并继续后续组合，最终返回非零退出码；编译失败立即停止。
CSV和表格在每次运行后刷新，已完成结果可以保留。脚本不会自动重试或恢复未完成批次。

## 可复现性与保持的行为

实验副本把两种随机来源统一为固定种子的 `mt19937_64`，对芯粒按名称、空闲 TOB 按坐标排序。
整数和浮点随机数采用明确映射，避免 `uniform_distribution` 的标准库差异。
冒烟比较两次默认配置的目标、全部逐层轨迹及初始/最终位置；不比较时间戳和耗时。
不同编译器的浮点 `exp` 在接受边界仍可能存在细微差异，环境信息会保留。

保留当前搜索算法的目标函数、邻域规则、Metropolis准则、降温、提前停止和层末最优记录；
不是记录每个候选过程中出现过的全局最低值。交换概率仍为 `0.5 + 0.2*T/Tinit`。
没有顺便修复原 `randomly_get_a_idle_tob()` 用右开区间 `[0, size()-1)` 抽样的行为：
它会排除排序后最后一个空闲 TOB；本组测例只有12芯粒的case12会用到该分支，始终有4个空闲位置。
因此结果反映采用固定随机源和稳定候选顺序的当前布局算法，不保证等于原CLI某次随机运行。
仪表插入点有严格匹配检查，未来源码变动导致匹配失败时会中止，避免悄悄漏记统计。
