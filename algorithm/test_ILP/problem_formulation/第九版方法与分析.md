## 第九版

    在第七版方法的基础上做修改

### 修改1: 软破坏SimpleMCF阶段ILP模型的对称性（已修改，已测试）

目前SimpleMCF阶段求解速度比较慢，其中一个原因是SimpleMCF的模型具有较强的对称性，存在较多权重相同的最优路径。所以修改计划是在SimpleMCF的warm start求解结束之后，对于每一个origin net，把求出来的路径使用的边对应的权重设为0.95，没有使用的边权重仍然是1（和原来一样），然后在原来的目标函数当中给x乘上对应边的权重

1. 同时开启--enable-pre-routing和--enable-mcf-obj的时候应用该策略，该策略并不单独对应一个CLI参数
2. 只对origin内成功求解warm start的边设0.95
3. 重试的时候回到全1
4. 0.95这个值可以写在程序里面，但是最好用一个比较显眼的参数，这样如果我要调整可以自己找到这个参数进行修改

### 修改2: SimpleMCF 阶段 PNnet 使用 path bbox 裁剪（对齐 TTB），同时去除virtual_P/Nnode，直接使用SAT分配的track（已修改，已测试）

第七版起 PNnet 在 SimpleMCF 不裁剪（`snk` 连 unit 级 `vp`/`vn`）。第九版改为与 **TrackToBumpsNet 拆分 child（TTB）** 相同的 bbox 规则；**`snk` 仍为 `vp`/`vn`，不改为固定 `end_track`**。

bbox 来源：SAT 选定 `(start_track, end_track)` 在 path precompute 中的路径 bbox（与 Tnet/TTB 相同）。

| 情况 | `is_multi_fanout` | MCF bbox 模式 | 裁剪范围 |
|------|-------------------|---------------|----------|
| 同 origin 仅 1 个 child（PNnet 或 TTB） | `false` | `SimpleCommodity` | 该 record 的 path bbox |
| 同 origin ≥2 个 PNnet/TTB child | `true` | `SimpleOriginGroup` | 各 child path bbox 的 `RectHull` |

实现要点（`mcf_bbox.cc`、`effective_bbox_for_simple_commodity`）：PNnet 不再跳过 bbox 管线；`arc_allowed_in_mcf_bbox` 对 virtual arc 及 endpoint（含 `vp`/`vn`）的例外不变。

边界：若裁剪后 `src` 与 `snk` 在 bbox 内不连通，按现有规则 `bbox disconnected` 失败并 tier 扩展；warm start 与 Gurobi 共用 `effective_bbox_for`。

### 修改3: 调整BusMCF求解结果的标记，并消除SimpleMCF warm start门控受到BusMCF结果的影响

我觉得Gurobi求解结果的标记还应该丰富一些，针对GRB_OPTIMAL和GRB_SUBOPTIMAL分别标记，同时这两种情况都应该认为得到了一个可以用的解。由于目前不采用限制时间的策略，所以不应该出现GRB_TIME_LIMIT的情况。剩下的情况视为求解失败。你看看这样是否合理？如果合理，看看修改这个状态标记之后哪些相关的地方也需要修改？

一个可能的方案是：显式字段，不再靠 ok 推断
在 StageSolveResult 增加 solution_class，表示求解结果，不再用ok笼统的推断。

优点： 标记最丰富，日志/统计最清晰。
缺点： 所有原来读 ok 的地方要确认是否应读 solution_class

另一个问题是，目前SimpleMCF warm start的启动依赖于BusMCF的求解状态，如果BusMCF没有得到最优而重启求解，后续的SimpleMCF不会进行warm start（可以看日志output/debug.log关于BusMCF和SimpleMCF求解信息），但这是错误的，我希望SimpleMCF的warm start只要在Bu是MCF求解是有可行解（GRB_OPTIMAL和GRB_SUBOPTIMAL）的情况下都进行。如果BusMCF失败，应该tier++并执行失败后重新SAT的流程。

1. solution class包含
Optimal
Suboptimal
Time-limit -> 这个应该报WARNING，因为目前不会给Gurobi设置time limit
Failed  // INFEASIBLE / INF_OR_UNBD / NUMERIC / ...等求解失败的情况，以及bbox disconnected 等 Gurobi 未跑
Skipped,     // --disable-bus-mcf

原来的ok = Optimal || Suboptimal || Skipped

2. SUBOPTIMAL 必须提取解
GRB_OPTIMAL 和 GRB_SUBOPTIMAL 都要读 X、填 used_edges / paths / objective
SUBOPTIMAL 时 ObjVal 可信、可记录日志
 
3. Bus/Simple统一，1. 的修改也适用于SimpleMCF

4. BusMCF如果带warm start的情况得到Suboptimal，可以不用重试了，直接接受这个结果。SimpleMCF也一样

5. 失败路径与 tier++

凡 solution_class 为 Failed 或 TimeLimit → ok=false → 本轮 all_ok=false → 走第七版 tier++；Optimal/Suboptimal/Skipped 不 tier++。
bbox disconnected、Gurobi 不可行/异常、NUMERIC 等一律 Failed；GRB_TIME_LIMIT 标 TimeLimit 并打 WARNING（不应出现，出现则按失败处理）。
retry_hints / bus_failure_unlocalized 规则不变，仅把判断从「笼统 !ok」改为「Bus 为 Failed/TimeLimit」；Suboptimal 不写 retry_hints。
SimpleMCF warm start 门控：Bus 为 Optimal、Suboptimal 或 Skipped 时执行；Failed/TimeLimit 不执行。
SimpleMCF 与 BusMCF 一致：warm start 得 Suboptimal 直接接受，不重试。
solve_binary_columns_with_gurobi 在底层按 status 设 solution_class，INFEASIBLE 不得 ok=true。
