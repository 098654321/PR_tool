## 纯SAT建模可行解

前面第1～12版方法有一个问题：如果把布线流程拆解成TOB SAT + COB MCF，那么如何考虑两个步骤的衔接？也就是说，要如何考虑TOB的分配结果对后续布线的影响？在问题规模不大的情况下，完全可以把TOB和COB建模到一张完整的有向图当中，一起求解整个问题。这样可以发挥SAT方法完整搜索解空间、充分探索可行解/证明问题无解的优势。





## 有向图建模

#### COB&track阵列建模

$G^c=(V^c, E^c)有向图; V^c=\{interposer上用全局坐标描述的所有track\}; E^c$用于描述连接关系的建模思路如下：

COB阵列一共9行*12列的COB，每个COB是正方形，正方形的四条边上各自连接了track。同一列上的相邻两个COB之间通过垂直方向的128条track相连，同一行上的相邻两个COB之间通过水平方向的128条track相连，例如，COB(0, 0)的右侧边和COB(0, 1)左侧边之间通过128条水平track连接，这些track右端接在COB(0, 1)的左侧边上，左端接在COB(0, 0)的右侧边上；COB(0, 0)的上侧边和COB(1, 0)下侧边之间通过128条垂直track连接，这些track的下端接在COB(0, 0)的上侧边，上端接在COB(1, 0)的下侧边上 。这样整个COB阵列构成了一个Mesh网络。除了阵列内部COB之间的track以外，阵列的最外围一圈COB当中，每个COB朝向外侧的那条边上也有128个track，这些track构成了整个COB阵列当中最外围的track。每一个track构成一个节点。

COB之间有可能存在TOB，TOB位于坐标是(x, y)和（x-1, y）的两个COB之间。所有的TOB所在的两个COB坐标组合包括：

| TOB编号 | 上方COB坐标 | 下方COB坐标 |
| :-----: | :---------: | :---------: |
|    0    |   (1, 0)    |   (0, 0)    |
|    1    |   (1, 3)    |   (0, 3)    |
|    2    |   (1, 6)    |   (0, 6)    |
|    3    |   (1, 9)    |   (0, 9)    |
|    4    |   (3, 0)    |   (2, 0)    |
|    5    |   (3, 3)    |   (2, 3)    |
|    6    |   (3, 6)    |   (2, 6)    |
|    7    |   (3, 9)    |   (2, 9)    |
|    8    |   (5, 0)    |   (4, 0)    |
|    9    |   (5, 3)    |   (4, 3)    |
|   10    |   (5, 6)    |   (4, 6)    |
|   11    |   (5, 9)    |   (4, 9)    |
|   12    |   (7, 0)    |   (6, 0)    |
|   13    |   (7, 3)    |   (6, 3)    |
|   14    |   (7, 6)    |   (6, 6)    |
|   15    |   (7, 9)    |   (6, 9)    |

track之间的连接关系要用COB内部的开关表示。COB内部首先由16个正方形的COBUnit，COB四条边上的每一条边上的track都会被映射到一个COBUnit，成为这个COBUnit对应正方形边上的一个端口。一个COBUnit四条边上的端口之间的连接关系有Wilton变换给定。也就是说，例如COB（0，0）右侧边的一条track可以通过“COB右侧边track->某COBUnit右侧边某端口->COBUnit::right_index_map_up_index()->COBUnit上侧边某端口->该端口映射回COB上侧边某track”的方式计算出右侧边的这个track和上侧边某条track有连接关系，从而在这两个track代表的node之间建立连接的边。

auto COBUnit::left_index_map_up_index(std::usize index) -> std::usize {
    COBUnit::assert_index(index);

    COBUnit::assert_index(index);

    COBUnit::assert_index(index);
    if (index == 0) {

    } else {
        return index - 1;
    }
}

    COBUnit::assert_index(index);

        return 0;
    } else {

    }
}

auto COBUnit::right_index_map_down_index(std::usize index) -> std::usize {
    COBUnit::assert_index(index);
    if (index == COBUnit::WILTON_SIZE - 1) {
        return COBUnit::WILTON_SIZE - 1;
    } else {
        return COBUnit::WILTON_SIZE - 2 - index;

    COBUnit::assert_index(index);
    if (index == COBUnit::WILTON_SIZE - 1) {
        return COBUnit::WILTON_SIZE - 1;
    } else {

    COBUnit::assert_index(index);

    COBUnit::assert_index(index);
    return index;

#### TOB建模

每一个TOB分成两个bank，这两个bank当中的结构是对称的。 每个bank包含：

- 8组bump，每组包含8个bump

- 同时，每组bump拥有8根水平开关线，每一个bump最多可以选择其中的一个进行连接，而每一根水平开关线最多只能被一个bump选择。
- 有8组垂直开关线，每一组有8根。对于每一组水平开关线，组内的第$i$根水平线可以连接到第$i$组垂直线，然后在这一组8根垂直线中最多挑选一根。同样的，每一个垂直线只能被选择一次

两个bank各有64根垂直线，记bank0的垂直线编号是0~63，bank1的垂直线编号是64~127，这样第$k, k+64$号垂直线构成一组。一组垂直线可以选择straight/swap的连接模式，其中straight模式把这两根垂直线接到第$k, k+64$号track，而swap模式把这两根垂直线接到第$k+64, k$号track

基于这样的结构，TOB的建模是

- 每一个bump和每一根水平开关线是一个节点。在每一组内，每个bump有8条出度边，每一条指向同组内的一根水平线（双向的边）

- 同一个 bank 中，每一组的第 \(i\) 根水平线可以连接到第 \(i\) 组垂直线中的一根。因此每一根垂直线也建成一个节点，水平线节点到候选垂直线节点之间建立双向物理连接；在有向图中表示为两条方向相反的 arc。

- bank0的每一个垂直线节点（第i号垂直线）接到第i，i+64号track节点，bank1的每一个对应的垂直线节点（第i+64号垂直线）也能接到第i，i+64号track节点，并且这四个连接都是双向的，在有向图中表示为两条方向相反的arc。但是实际求解的时候，需要加上约束，表明straight/swap的连接模式

通过上述方式，可以把TOB建模成一个有向图，并且和track的图接起来

## 变量定义

1. 对于有向图当中的每一个节点，定义变量\(P_{s, n}\)表示“节点n是否被源s驱动” 
2. \(p_{j,i,v}\)表示一对源、汇($s_j$, $t_i$)是否使用节点v
3. \(x_{j,i,u,v}\)表示一对源、汇($s_j$, $t_i$)是否使用边(u, v)



## 约束条件

1. 常量约束

   - 对于每一个源s，有$P_{s, s} = true$

   - 对于任意两个不相同的源s1, s2，有$P_{s_1,s_2}=false$

   - 如果节点v不在某条net预先求解的scope当中，那么$P_{net的所有source,v}=false$

   - 对于一个net的所有source s1, s2, ...和所有sink t1, t2, ...，满足
     $$
     ExactlyOne_j\{p_{j,i,t_i}\}, \qquad i = 1, 2, ...
     $$

   ==（注：和论文相比，这里多了多源多汇net的需求）==

2. 变量关系
   $$
   p_{j,i,s_j} \Leftrightarrow p_{j,i,t_i}
   $$
   
   $$
   P_{s_j,v}\Leftrightarrow
   \bigvee_i p_{j,i,v}, v \neq s_j
   $$

   $$
   x_{j,i,u,v}\Rightarrow p_{j,i,u}\land p_{j,i,v}
   $$
   
   ==（注：这一点是比论文多出来的）==
   
3. Connectivity Constraints

   源：
   $$
   \sum_{x\in O(s_j)}x_{j,i}=p_{j,i, t_i},
   \qquad
   \sum_{x\in I(s_j)}x_{j,i}=0
   $$
   汇：
   $$
   \sum_{x\in I(t_i)}x_{j,i}=p_{j,i,t_i},
   \qquad
   \sum_{x\in O(t_i)}x_{j,i}=0
   $$
   中间点（注意不能包含源和汇）：

$$
p_{j,i,v}\Leftrightarrow
\bigvee_{x\in I(v)}x_{j,i},
\qquad
\operatorname{AtMostOne}(I(v))
$$

$$
p_{j,i,v}\Leftrightarrow
\bigvee_{x\in O(v)}x_{j,i},
\qquad
\operatorname{AtMostOne}(O(v))
$$

​	防止非激活的(s_i, t_j)形成独立的环：
$$
p_{j,i,v}\Rightarrow p_{j,i,t_i}
$$
==（注：和论文相比，connectivity constraints需要修改）==

3. Exclusivity Constraints

   任意的两个源s1和s2（可以是同一个net的两个不同的源，也可以是不同net的两个源），满足：
   $$
   \overline{P_{s1,n}} \lor \overline{P_{s2,n}}
   $$



==（注意，目前的建模允许存在独立的冗余环，但是这不影响最终的解）==



## 特殊处理

1. v-line - track的连接模式

   - 给全局所有TOB中的每一组v-line定义一个变量$M_g$，表示第g组v-line连接到track的时候取straight/swap模式（true/false）

   - 对第g组定义边集合：
     $$
     E_g^{str}=\{v_k\leftrightarrow t_k,\;
     v_{k+64}\leftrightarrow t_{k+64}\}\\ 
     E_g^{swp}=\{v_k\leftrightarrow t_{k+64},\;
     v_{k+64}\leftrightarrow t_k\}
     $$

   - 增加约束条件：
     $$
     x_{j,i,c_{str}} \Rightarrow M_g，\forall{j}, \forall{i}, \forall{c_{str} \in E^{str}_g}\\
     x_{j,i,c_{swp}} \Rightarrow \neg M_g，\forall{j}, \forall{i}, \forall{c_{swp} \in E^{swp}_g}
     $$
     

2. Bus等长约束

   每一个Bus线由多个2-pin net构成，同一个bus内的2-pin net长度必须一样。其中长度可以用一条路径里面节点的数量计算。从语义上讲，如果用n表示某个bus里面的2-pin net，定义：
   $$
   L_n=\sum_{v}p_{n.s,n.t,v}
   $$
   然后满足：对 bus \(B\)，选择一个参考成员 \(n_0\)：
   $$
   L_n=L_{n_0},
   \qquad
   \forall n\in B\setminus\{n_0\}
   $$
   纯 SAT 中建议使用 unary totalizer。定义：

   \[ \ell_{n,k}\Leftrightarrow (L_n\ge k) \]

   然后约束：

   \[ \ell_{n,k}\Leftrightarrow\ell_{n_0,k}, \qquad\forall k \]

3. 对Bus去除冗余环路

   当前模型允许：

   \[ \text{主路径}+\text{独立环} \]

   而 \(\sum_v p_{n,v}\) 会把环上的节点也算入长度，SAT 可能通过添加环给较短的 bus member“补长度”。

   对 bus member \(n=(s_n,t_n)\) 的每个节点定义有界整数：

   \[ d_{n,v}\in\{0,1,\ldots,H_B\} \]

   其中 \(H_B\) 是允许的最大路径节点数。规定：

   \[ d_{n,s_n}=1 \]

   对每条边：

   \[ x_{n,u,v}\Rightarrow d_{n,v}=d_{n,u}+1 \]

   这样如果存在环，那么环上有一点的d会产生两个不同的值，引发矛盾

4. TOB开关选择的唯一性

   开关虽然有多个连接指向，但是：每个 bump 最多连接一个 h-line；每个 h-line 最多连接一个 bump；每个 h-line 最多连接一个 v-line；每个 v-line 最多连接一个 h-line。

   为每个无向物理开关定义聚合使用变量：
   $$
   Y_{\{u,v\}}\Leftrightarrow \bigvee_{j,i} (x_{j,i,u,v}\lor x_{j,i,v,u})
   $$
   然后分别建立两个 partial matching：
   $$
   AtMostOne(\{Y_{\{b,h\}}\mid h\in H(b)\})\\
   AtMostOne(\{Y_{\{b,h\}}\mid b\in B(h)\})\\
   AtMostOne(\{Y_{\{h,v\}}\mid v\in V(h)\})\\
   AtMostOne(\{Y_{\{h,v\}}\mid h\in H(v)\})
   $$
   

   



## scope求解

在求解之前可以对搜索空间剪枝，排除一些不必要的节点，也就是模仿论文当中先求一个“scope”的方式。这个scope求解可以沿用第二版方法中的求解方法，并且做一些修改。修改后的内容如下：

首先，所有net可以分为Tnet, Bnet, PNnet。这三种net的意义如下：

|    类型    |                意义                | 起点Pstart      | 终点Pend |
| :--------: | :--------------------------------: | --------------- | -------- |
| Pnet和Nnet |        连接到“1/0”端口的net        | 一组给定的track | Bump     |
|    Tnet    | 除了P/Nnet以外，端口含有track的net | 一个给定的track | Bump     |
|    Bnet    |         端口全是bump的net          | Bump            | Bump     |

对于同步线和PNnet，需要做几何拆分。拆分时必须保留子项和原始net的对应关系：

|                             类型                             |                           拆分方式                           |
| :----------------------------------------------------------: | :----------------------------------------------------------: |
| 同步总线（含多根2-pin net，且这些2-pin net要么都是Tnet，要么都是Bnet） |                  取出里面的每一个2-pin net                   |
|                          Pnet和Nnet                          | 按起点track生成几何子项。每个子项由一个track和原始net的全部bumps组成，用于计算该track对应的局部scope |

这里的“拆分”只服务于bounding box计算，不产生新的SAT求解net。`build_routing_nets`对每个原始`circuit::Net`只生成一个`RoutingNet`；SAT始终以原始net为求解单位，并在同一个net内保留全部source、sink demand及其固定配对或候选source关系。几何子项只用于分别计算局部bounding box，随后合并为原始net的scope。

然后给每个几何子项计算一个bounding box：

1. Bnet
