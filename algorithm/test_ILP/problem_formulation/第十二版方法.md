## 第十二版方法与分析

本版基于第十版当前实现继续修改，目标是加速 SimpleMCF 中多扇出 origin 的优化求解。核心思路是：**先用当前 SimpleMCF 模型得到一棵可行布线树，再基于这棵树提取重要节点并拆成若干 2-pin segment，最后在保留 parent origin 级 `x^H/o^H` 共享语义的前提下重建 SimpleMCF 模型求解。**

**启用条件**：仅当 CLI 传入 `--enable-mcf-obj` 且该 COBUnit 存在 multi-fanout SimpleMCF origin 时启用两阶段 tree-refine；未开 `--enable-mcf-obj` 时行为与第十版完全相同（单次可行性 SimpleMCF）。不新增其它命令行参数。代码实现放在 `algorithm/test_ILP/mcf/`（`cob_mcf_router.cc` 编排 + `mcf_simple_tree_refine.cc` 树压缩），不修改 SAT 编码、path precompute、BusMCF 建模和外层 tier 语义。

---

### 1. 动机

当前 case7 的主要耗时集中在 SimpleMCF 的多扇出 origin。第十版已经通过一些修改缩小并强化了模型，但多扇出 origin 仍有一个结构性问题：

1. 同一 origin 下多个 child commodity 共用一组 `x^H_e/o^H_i`；
2. origin group 的 bbox 通常是多个 child path bbox 的 `RectHull`；
3. 每个 child 的 `f` 都可以在较大的 origin bbox 内流动；
4. Gurobi 需要同时决定“在哪里分支”和“每个 terminal 如何连接”，LP relaxation 与整数搜索仍然较重。

第十二版不再让 Gurobi 在完整 origin bbox 中自由寻找整棵树，而是先让原模型快速找出一棵可行树，然后把这棵树的拓扑骨架固定为一组 2-pin segment。第二阶段只在每个 segment 的局部 bbox 内重新寻路，从而减少 `f` 变量和流守恒约束，同时保留同一 origin 内 track/node 共享。

注意：本版不是把多扇出 net 拆成互相独立的普通 2-pin net。若这样做，不同 segment 会在 `edge_capacity` / `node_capacity` 下互相排斥，反而破坏同一 net 共享布线树的合法语义。本版的 segment 只是 **2-pin flow commodity**；它们仍属于同一个 parent origin，并共享同一组 `x^H/o^H`。

---

### 2. 总体流程

当前流程为：

```text
SAT TOB allocation
  -> build MCF bbox context
  -> BusMCF
  -> SimpleMCF per COBUnit
```

本版只修改每个 COBUnit 内的 SimpleMCF，且仅在 `--enable-mcf-obj` 时生效：

```text
for each COBUnit c inside run_simple_mcf_unit_with_bbox_retry:
    if NOT enable_mcf_obj OR unit c has no multi-fanout SimpleMCF origin:
        run current SimpleMCF once (feasibility or min Σ x per flag)
        return result

    for attempt in bbox_retry_loop:                    # 方案 A
        # 第一阶段：原模型快速求可行树
        stage1 = solve_simple_mcf_unit(pass=TreeSeed, MIPGap=0.30)
        if stage1 failed:
            bbox expand; continue attempt              # 沿用现有 bbox retry

        compress each multi-fanout origin into segments
        build refined commodity list for stage2

        # 第二阶段：segment refinement（禁用 pre-routing BFS）
        stage2 = solve_simple_mcf_unit(
            pass=Refine,
            commodities=refined,
            MIP start from stage1 incumbent projection)
        if stage2 failed:
            ERROR; unit ok=false; return               # 不 fallback，不 tier++

        merge segment paths to parent-origin McfPathInfo
        return stage2 (solve_ms = stage1 + stage2)
```

第一阶段失败仍按现有规则处理（bbox expand → 耗尽后 tier++）。第二阶段失败**不触发 tier++**；因 stage1 已证明当前 SAT/Bus residual 下可布通，stage2 失败视为建模/实现错误，记录 **ERROR** 并使 unit 失败。

#### 2.1 与 bbox retry 的嵌套（方案 A）

tree-refine 嵌套在 `run_simple_mcf_unit_with_bbox_retry` 的 **每次 bbox attempt** 内：stage1 失败才 expand bbox 并重试；stage1 成功后同一次 attempt 内立即 compress 并跑 stage2。stage2 失败不 expand bbox、不回到 stage1，直接 ERROR 结束该 unit。

---

### 3. 第一阶段：原 SimpleMCF 快速可行树

第一阶段使用当前 `solve_simple_mcf_unit()` / `solve_simple_mcf_component()` 的原始模型：

- commodity 仍来自 `prepare_commodities()`；
- origin group 仍由 `build_origin_groups()` 根据 `(cob_unit, simple_origin_group_key(record))` 构造；
- 多扇出 origin 仍使用 origin group bbox；
- conflict graph 分解仍以 **origin** 为顶点（`preview_simple_candidate_resources`）；
- Bus residual edge/node 过滤、`f_le_x_lower`、`f_le_x_upper`、`x_le_o`、degree 约束、`o_endpoint_eq` 均保留；
- 若开启 `--enable-pre-routing`，warm start 仍使用 `route_simple_mcf_stage_warm_start_by_origin()`。

第一阶段目标不是严格证明全局最优，而是尽快得到整数可行树。Gurobi 参数：

```text
MIPGap = 0.30
```

```cpp
constexpr double kSimpleMcfTreeSeedMipGap = 0.30;
```

第一阶段仍接受 `Optimal` / `Suboptimal`，并提取 `f` 解与 `used_edges`/`used_nodes`。日志需打印 `pass=tree_seed` 与 `mip_gap=0.30`。

第一阶段输出使用 `StageSolveResult::paths`；`append_paths_from_f_solution()` 已为每个 commodity 提取 `McfPathInfo::unit_paths`，作为建树输入。

---

### 4. 多扇出 origin 的树提取

对每个 SimpleMCF unit，在第一阶段成功后，按现有 origin group 重新分组：

```text
key = (cob_unit, simple_origin_group_key(record))
```

只处理 `group.is_multi_fanout == true` 的 origin。普通 2-pin origin 不进入 segment refinement。

对每个多扇出 origin，收集其所有 child commodity 在第一阶段结果中的路径（`McfPathInfo::unit_paths`）。将这些路径取 union：

```text
tree_nodes = union of all physical nodes in origin_paths
tree_edges = union of all consecutive physical undirected edges in origin_paths
```

处理规则：

- virtual node 不参与（当前实现基本不使用 virtual node）；
- physical endpoint node 必须保留；
- physical branch node 在 `tree_edges` 中 degree >= 3 时保留；
- degree == 2 的中间节点不作为 segment 端点，仅作 segment 内部 guide path；
- degree == 1 的非原始 terminal 叶子应剪掉；原始 terminal 保留。

union 不连通或某原始 terminal 不在 union 中 → WARNING，该 origin 回退原始 child commodities。

---

### 5. important node 与 segment 生成

```text
important_nodes =
    original physical endpoints
    ∪ physical nodes with degree >= 3 in first-stage path union
```

在 `tree_edges` 上从每个 important node 沿 degree-2 链走到另一个 important node，形成 segment：

```text
segment.src, segment.snk, segment.guide_path, segment.bbox
segment.parent_origin_key, segment.parent_record_indices
```

每条 tree edge 只属于一个 segment（无向边集划分，visited-edge 遍历；端点去重 `min(u,v),max(u,v)`）。若有环，先剪非 terminal 叶子。压缩结束校验 `visited_edges == |tree_edges|`。

---

### 6. segment bbox

每个 segment 的 `bbox_override` 由 `guide_path` 相邻物理弧的 `arc.cob`（及 straight-through 邻接 COB）做最小外接矩形，与 `arc_allowed_in_mcf_bbox` 坐标系一致；单节点退化用 `track_row/track_col`。arc 过滤对 refined segment 使用 `McfArcBBoxMode::SimpleExplicit` + `bbox_override`。`src/snk` 享有第七版 §6.2 endpoint 接入例外。bbox 构造失败、`commodity_bbox_connected` 失败 → 该 origin 回退 child commodities。

---

### 7. 第二阶段 SimpleMCF 建模语义

| origin 类型 | 第二阶段处理 |
|---|---|
| 普通 2-pin origin | 保留原 `PreparedCommodity` |
| 多扇出 origin，segment 构造成功 | 用 segment commodities 替换 child |
| 多扇出 origin，segment 构造失败 | 保留原 child commodities |

segment 共享 parent origin 的 `x^H/o^H`；`f` 仅在各自 segment bbox 内；`build_origin_groups()` 将同一 parent 的 segment 归入同一 group（`origin_name/origin_uid` 继承 parent）。

conflict graph 分解：stage2 以 **每个 2-pin commodity（含 segment）** 为顶点（`preview_simple_refine_candidate_resources`），与 stage1 的 origin 级分解不同。

`PreparedCommodity` 扩展字段：

```cpp
bool is_refined_segment{false};
std::optional<McfCommodityBBox> bbox_override{};
std::Vector<int> guide_path{};
std::String synthetic_label{};
```

synthetic `record_id`（仅 stage2 内部 warm-start 键）：

```cpp
constexpr std::size_t kMcfSyntheticRecordIdBase = 1'000'000'000ULL;
constexpr std::size_t kMcfSyntheticRecordIdPerUnit = 10'000ULL;
synthetic_id = kMcfSyntheticRecordIdBase + unit * kMcfSyntheticRecordIdPerUnit + local_seg_idx;
```

### 8. 对当前代码的修改位置

#### 8.1–8.4

见 §7 与第十版 SimpleMCF 建模；`effective_bbox_for_simple_commodity` 对 refined segment 优先 `bbox_override`；refined segment arc 过滤使用 `McfArcBBoxMode::SimpleExplicit` + `bbox_override`（不经 `ctx.per_commodity` 查表）。

#### 8.5 第二阶段 MIP start（incumbent 投影）

第二阶段 **不使用** `run_simple_warm_start_for_unit`（pre-routing BFS）。当前实现 **8.5a+8.5b**（8.5c 普通 2-pin、8.5d fallback child 待后续）：

- **共享 `x^H`**（8.5b）：stage1 `used_edges` 中物理无向边 → stage2 同 origin `x` `Start=1`；
- **共享 `o^H`**（8.5b）：stage1 `used_nodes` → stage2 同 `(h,node)` 的 `o` `Start=1`；
- **segment `f`**（8.5a）：沿 `guide_path` 相邻弧设 `f=1`（与 stage1 树一致）。

`McfPathInfo::record_indices` 保存真实 child record ids；synthetic `record_id` 不进入最终 paths。

#### 8.6 失败与回退

| 事件 | 行为 |
|------|------|
| 第一阶段失败 | 现有 bbox retry / tier++ |
| segment 构造失败（单 origin） | WARNING；该 origin 保留 child commodities |
| 第二阶段 Gurobi 失败 | **ERROR**；unit `ok=false`；**不 fallback**；**不 tier++** |

---

### 9. 解提取与统计

第二阶段成功后，在写入 `StageSolveResult::paths` **之前**将 segment paths 合并为 parent-origin 的 `McfPathInfo`（每个 child 一条 path）。`post-solve` / `--show-resource-usage` 使用合并后路径。线长按 path union 计 physical track；bump 只按原始 child records 计。

---

### 10. 与第八版的区别

1. 第八版求解前 Steiner 拆解；本版先用当前模型得可行树再压缩；
2. 第八版 segment 像独立 commodity；本版共享 parent `x^H/o^H`；
3. 本版树来自 stage1 可行解；
4. 本版 stage2 失败报 ERROR（建模问题），不静默回退。

---

### 11. 预期效果

收益：多扇出 origin 的 `f`/flow 行减少、segment bbox 更小、分支点固定、LP 更紧。代价：含 multi-fanout 的 unit 在 `--enable-mcf-obj` 下跑两次 SimpleMCF；stage2 拓扑固定不保证全局最优。
